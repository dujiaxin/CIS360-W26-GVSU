# Data Fusion Knowledge Management System - Tutorial

## Overview

This tutorial walks through how we built a **web-based knowledge management system** that consolidates data fusion research data from 33+ individual Excel spreadsheets into one unified, searchable, and editable application.

Each Excel file was submitted by a student and contains metadata about academic papers related to **data fusion** -- including paper details, fusion methods, and datasets used. The system imports all of this data into a single SQLite database and provides a clean web interface for browsing, searching, filtering, and managing the records.

### What the System Does

- **Imports** 34 spreadsheet files (33 `.xlsx` + 1 `.csv`) automatically
- **Normalizes** varying column names and sheet structures across files
- **Stores** everything in a structured SQLite database
- **Serves** a Bootstrap-styled web interface with:
  - Dashboard with statistics and top fields/publishers
  - Browsable, searchable paper/method/dataset tables
  - Detail pages with cross-linked related records
  - Contributor tracking (who submitted what)
  - Full CRUD (Create, Read, Update, Delete) for all records
  - Global keyword search across all entities

## Step 1: Understanding the Data

### The Challenge

Every student submitted an Excel file with data fusion research information, but the formats varied:

**Format A -- Three-Sheet (most common):**
- **Sheet "DOI"** (or "Paper Summary"): Paper metadata (DOI, title, authors, abstract, publisher, field of study, etc.)
- **Sheet "Fusion_Method"** (or "Fusion Method"): Method name, description, uncertainty types U1 and U3
- **Sheet "Data"**: Dataset name, URL, type, collection method, uncertainty type U2, spatial/temporal coverage

**Format B -- Single-Sheet (some files):**
- One flat table with columns: Paper Title, Dataset Name, Method Name, Uncertainty Type, Description

**Column Name Variations:**
Students used different column names for the same data. For example:
- Author field: `Author`, `Authors`, `Name (Author)`
- Publication date: `PublicationDate`, `Publication Date`, `Publication_Date`
- Field of study: `Field of Study`, `Field of Study ` (with trailing space), `FieldOfStudy`

The import script handles all of these variations through **column name normalization**.

## Step 2: The Import Script (`import_data.py`)

### How It Works

The import script follows this pipeline:

```
Excel/CSV Files  -->  Column Normalization  -->  SQLite Database
```

### Key Design Decisions

#### 1. Column Name Normalization

Every column name is normalized to a canonical form by:
- Converting to lowercase
- Removing non-breaking spaces (`\xa0`)
- Replacing spaces with underscores
- Stripping special characters

Then a mapping dictionary translates variations to standard names:

```python
PAPER_COL_MAP = {
    'doi': 'doi',
    'title': 'title',
    'paper_title': 'title',          # variant
    'author': 'author',
    'authors': 'author',             # variant
    'name_author': 'author',         # variant
    'publicationdate': 'publication_date',
    'publication_date': 'publication_date',
    # ... and so on
}
```

#### 2. Sheet Detection

The script uses a two-pass strategy to identify which sheet contains which data:

1. **Name matching** -- looks for keywords like "doi", "fusion", "method", "data" in sheet names
2. **Header detection** -- if name matching fails (e.g., sheets named "Sheet1", "Sheet2", "Sheet3"), it reads the header row and classifies based on column names

```python
def detect_sheet_type(xls, sheet_name):
    """Detect if a sheet contains papers, methods, or datasets based on its header columns."""
    df = pd.read_excel(xls, sheet_name=sheet_name, nrows=0)
    cols_norm = set(normalize_col(c) for c in df.columns)
    if 'method_name' in cols_norm or 'methodname' in cols_norm:
        return 'method'
    if 'data_name' in cols_norm or 'dataname' in cols_norm:
        return 'dataset'
    if 'doi' in cols_norm and ('title' in cols_norm or 'abstract' in cols_norm):
        return 'paper'
    return None
```

#### 3. Contributor Tracking

Each record is tagged with the contributor who submitted it, derived from the filename:

```python
def contributor_name(filename):
    """Derive contributor name from filename."""
    name = Path(filename).stem
    for suffix in [' Data Fusion', ' Data', ' Dataset Midterm Part 2', 'DataFusionKg']:
        name = name.replace(suffix, '')
    name = name.replace('_', ' ').strip()
    if name[0].islower():
        name = name.title()
    return name
```

### Database Schema

```sql
CREATE TABLE contributors (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    source_file TEXT NOT NULL UNIQUE
);

CREATE TABLE papers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    doi TEXT,
    title TEXT,
    author TEXT,
    publication_title TEXT,
    publication_date TEXT,
    url TEXT,
    keywords TEXT,
    abstract TEXT,
    publisher TEXT,
    field_of_study TEXT,
    is_data_fusion TEXT,
    classification_reason TEXT,
    contributor_id INTEGER,
    FOREIGN KEY (contributor_id) REFERENCES contributors(id)
);

CREATE TABLE methods (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT,
    method_key TEXT,
    doi TEXT,                    -- links to papers.doi
    description TEXT,
    u1 TEXT,                    -- Uncertainty Type 1
    u3 TEXT,                    -- Uncertainty Type 3
    contributor_id INTEGER,
    FOREIGN KEY (contributor_id) REFERENCES contributors(id)
);

CREATE TABLE datasets (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    doi TEXT,                    -- links to papers.doi
    data_name TEXT,
    dataset_url TEXT,
    method_key TEXT,
    data_type TEXT,
    collection_method TEXT,
    u2 TEXT,                    -- Uncertainty Type 2
    spatial_coverage TEXT,
    temporal_coverage TEXT,
    format TEXT,
    license TEXT,
    provenance TEXT,
    contributor_id INTEGER,
    FOREIGN KEY (contributor_id) REFERENCES contributors(id)
);
```

The **DOI** field serves as the linking key between papers, methods, and datasets. Indexes are created on `doi` and `contributor_id` columns for fast lookups.

## Step 3: The Web Application (`app.py`)

### Architecture

The Flask app follows a standard pattern:

```
Browser Request  -->  Flask Route  -->  SQLite Query  -->  Jinja2 Template  -->  HTML Response
```

### Key Components

#### Database Connection Management

```python
def get_db():
    if 'db' not in g:
        g.db = sqlite3.connect(DB_PATH)
        g.db.row_factory = sqlite3.Row    # enables column-name access
    return g.db

@app.teardown_appcontext
def close_db(exc):
    db = g.pop('db', None)
    if db is not None:
        db.close()
```

Flask's `g` object stores the database connection per-request. `sqlite3.Row` allows accessing columns by name (e.g., `paper['title']`) instead of index.

#### Search Implementation

Search uses SQL `LIKE` with wildcards for substring matching:

```python
@app.route('/search')
def search():
    q = request.args.get('q', '').strip()
    like = f'%{q}%'
    found_papers = db.execute('''
        SELECT p.*, c.name as contributor_name FROM papers p
        LEFT JOIN contributors c ON p.contributor_id = c.id
        WHERE p.title LIKE ? OR p.author LIKE ? OR p.doi LIKE ?
              OR p.abstract LIKE ? OR p.keywords LIKE ?
        LIMIT 50''', (like, like, like, like, like)).fetchall()
    # ... similar for methods and datasets
```

#### Pagination

Lists are paginated with 25 items per page:

```python
page = int(request.args.get('page', 1))
per_page = 25
query += ' ORDER BY p.id DESC LIMIT ? OFFSET ?'
params.extend([per_page, (page - 1) * per_page])
```

## Step 5: Using the System

### Browsing Data

1. **Dashboard** (`/`) -- See overall statistics, top fields of study, top publishers, and the 10 most recently added papers.

2. **Papers** (`/papers`) -- Browse all papers. Use the search box to find papers by title, author, DOI, abstract, or keywords. Use the dropdown to filter by field of study.

3. **Methods** (`/methods`) -- Browse fusion methods. Search by method name, description, or DOI.

4. **Datasets** (`/datasets`) -- Browse datasets. Search by name, type, DOI, or collection method.

5. **Contributors** (`/contributors`) -- See each student's contributions with paper, method, and dataset counts.

### Searching

Use **Global Search** (`/search`) to search across all entity types at once. Enter any keyword and results are grouped by papers, methods, and datasets.

### Adding/Editing/Deleting Records

- Click **"+ Add Paper"** (or Method/Dataset) to create a new record
- Click **"Edit"** on any detail page to modify a record
- Click **"Delete"** on any detail page to remove a record (with confirmation)

### Re-importing Data

If you add new Excel files or modify existing ones:

```bash

```

Note: Re-importing drops and recreates all tables, so any manual edits made through the web UI will be lost. If you need to preserve manual edits, export them first.

## Key Concepts for Students

### 1. ETL (Extract, Transform, Load)

The `import_data.py` script is a classic ETL pipeline:
- **Extract**: Read data from Excel/CSV files using pandas
- **Transform**: Normalize column names, clean cell values, detect sheet types
- **Load**: Insert structured rows into SQLite tables

### 2. Web Application Architecture (MVC Pattern)

The system follows Model-View-Controller:
- **Model**: SQLite database + SQL queries
- **View**: Jinja2 HTML templates
- **Controller**: Flask route functions

### 3. Database Design

- **Normalization**: Data is split across related tables (papers, methods, datasets) to avoid redundancy
- **Foreign Keys**: `contributor_id` links records back to their source
- **Indexes**: Created on frequently-queried columns (doi, contributor_id) for performance
- **DOI as Linking Key**: The DOI field connects papers to their methods and datasets

### 4. Template Inheritance

Jinja2 template inheritance (`{% extends "base.html" %}`) eliminates HTML duplication. The base template defines the layout once; child templates only provide page-specific content.

### 5. Handling Messy Real-World Data

Real-world data is never clean. This project demonstrates:
- Column name normalization (handling spaces, cases, abbreviations)
- Multiple file format support (3-sheet vs. single-sheet vs. CSV)
- Sheet detection by header analysis when names are ambiguous
- Graceful handling of missing/empty values

## Troubleshooting

| Problem | Solution |
|---------|----------|
| `ModuleNotFoundError: No module named 'flask'` | Run `pip install flask pandas openpyxl` |
| `no such table: papers` | Run `python3 import_data.py` first to create the database |
| Port 5000 already in use | Change `app.run(port=5000)` to another port in `app.py`, or kill the existing process |
| Excel file shows 0 records | Check that the sheet names or column headers match expected patterns. The import script logs each file's results |
| `ERROR filename.xlsx: Worksheet index 0 is invalid` | The Excel file is empty or corrupted |
| Search returns no results | Search uses substring matching -- try shorter, more general keywords |
